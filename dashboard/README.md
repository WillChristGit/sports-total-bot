# SportsTotalBot Web Dashboard

A Flask-based web interface for viewing betting picks, historical performance, and statistics from SportsTotalBot.

## Quick Start

```bash
# From the project root
./run_dashboard.sh
```

That's it! The script will:
- Activate the virtual environment
- Check/install Flask if needed
- Start the server on port 5001
- Open your browser to `http://localhost:5001`

## Manual Start

If you prefer to start the dashboard manually:

```bash
cd /Volumes/LegbaSSD/bots/SportsTotalBot
source venv/bin/activate
python dashboard.py
```

The dashboard will be available at: **http://localhost:5001**

## Features

### Real-Time Picks Display
- View today's betting picks as soon as they're generated
- Auto-refreshes every 60 seconds
- Shows EV, win probability, confidence, and units for each pick
- Color-coded by bet type (totals, spreads)

### Historical Performance
- Browse picks from the past 30 days (configurable)
- View performance statistics by sport, bet type, and side
- Track EV distribution and best picks

### Statistics Overview
- Average EV, win probability, and confidence
- Breakdown by sport (NBA, etc.)
- Breakdown by bet type (total, spread)
- Breakdown by side (over/under/home/away)
- EV distribution categories (high/medium/low)

      "sport": "NBA",
      "bet_type": "total",
      "side": "under",
      "line": 234.5,

      "projected_value": 221.3,
      "ev": 8.52,

      "confidence": 70.0,

      "away_team": "Boston Celtics",

### GET /api/history
Get historical betting performance.

**Query Parameters:**
- `days` (optional): Number of days to look back (default: 30, max: 90)

**Response:**
```json
{
  "success": true,
  "period_days": 30,
  "total_picks": 150,
  "picks": [...],
  "stats": {
    "total_picks": 150,
    "avg_ev": 7.52,
    "avg_win_probability": 58.3,
    "avg_confidence": 65.0,

    "by_sport": {...},
    "by_bet_type": {...},
    "by_side": {...},
    "ev_distribution": {...}
  }
}
```

### GET /api/stats
Get summary statistics.

**Query Parameters:**
- `period` (optional): `today` or `history` (default: `today`)
- `days` (optional): If `period=history`, number of days to look back (default: 30)

**Response:**

## Dashboard Files

The dashboard serves static files from the `dashboard/` directory:

- `index.html` - Main dashboard interface
- `styles.css` - Dashboard styling
- `app.js` - Frontend JavaScript for data fetching and display

## Data Source

The dashboard reads pick data from JSON files generated by the bot:

- **Location:** `data/picks/`
- **File Pattern:** `daily_picks_YYYYMMDD.json`
- **Format:** Array of pick objects with game details, projections, and EV calculations

## How Picks Are Generated

1. Run the bot to generate today's picks:
   ```bash
   python3 main_v2.py
   ```

2. Picks are saved to `data/picks/daily_picks_YYYYMMDD.json`

3. Dashboard automatically loads and displays the picks

4. Dashboard caches picks for 60 seconds to reduce file I/O

## Troubleshooting

### Port Already in Use

If you get an error about port 5001 being in use:

```bash
# Find and kill the process using port 5001
lsof -ti:5001 | xargs kill -9

# Or change the port in dashboard.py (line 514):
# app.run(host='0.0.0.0', port=5002, debug=True)
```

### No Picks Showing

If the dashboard loads but shows no picks:

1. **Generate picks first:**
   ```bash
   python3 main_v2.py
   ```

2. **Check pick files exist:**
   ```bash
   ls -la data/picks/
   ```

3. **Verify today's date** - picks files are dated, check the filename matches today

4. **Force refresh** in the dashboard: Add `?refresh=true` to URL
   - `http://localhost:5001/api/picks?refresh=true`

### Flask Not Installed

If you get "ModuleNotFoundError: No module named 'flask'":

```bash
# Install Flask and dependencies
pip install flask flask-cors

# Or reinstall all dependencies
pip install -r requirements.txt
```

### Virtual Environment Issues

If you having venv problems:

```bash
# Recreate virtual environment
rm -rf venv
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

### Browser Won't Open

If the browser doesn't open automatically:

1. **Manual access:** Open http://localhost:5001 in your browser

2. **Check server is running:** You should see "Running on http://0.0.0.0:5001" in the terminal

3. **Check firewall:** Ensure port 5001 is not blocked

## Development

### Running in Debug Mode

The dashboard runs in debug mode by default (set in `dashboard.py`):

```python
app.run(host='0.0.0.0', port=5001, debug=True)
```

Debug mode provides:
- Auto-reload on file changes
- Detailed error messages
- Interactive debugger

**Warning:** Disable debug mode in production!

### Production Deployment

For production use, consider:

1. **Use a production WSGI server:**
   ```bash
   pip install gunicorn
   gunicorn -w 4 -b 0.0.0.0:5001 dashboard:app
   ```

2. **Disable debug mode** in `dashboard.py`

3. **Set up proper logging**

4. **Use nginx as a reverse proxy**

5. **Enable HTTPS** with a certificate

## Customization

### Change Port

Edit `dashboard.py` line 514:

```python
app.run(host='0.0.0.0', port=5002, debug=True)  # Change 5001 to desired port
```

### Change Refresh Interval

Edit `dashboard.py` line 35:

```python
REFRESH_INTERVAL = 120  # seconds (default: 60)
```

### Customize Dashboard UI

Edit the files in `dashboard/`:
- `index.html` - Layout and structure
- `styles.css` - Colors, fonts, spacing
- `app.js` - Data fetching and display logic

## Performance Tips

1. **Use caching** - Dashboard caches picks for 60 seconds by default
2. **Limit history** - When using `/api/history`, keep `days` parameter reasonable (default: 30)
3. **Generate picks periodically** - Run `main_v2.py` on a schedule for fresh data

## Security Notes

- **Local use only** - Dashboard binds to `0.0.0.0` but should be firewalled
- **No authentication** - Anyone with access can view picks
- **Debug mode** - Disable in production environments
- **CORS enabled** - Allows cross-origin requests from any domain
